## Implemented in the applied schema and server code

- Every public application table has RLS. User-visible metadata is owner-readable only; publication jobs, prices, credentials, metrics, payment outcomes and credits cannot be written by clients.
- The hosted Auth minimum password length is 12, matching signup/reset client validation. It was raised from 6 on 8 October after the authorized Dashboard login. Reopened settings and actual 5-/11-character password rejections verified the saved rule. This does not establish real confirmation/recovery email delivery or compromised-password screening.
- User-owned requests check both the verified user and existence of the JWT's session in `auth.sessions`. New policies reject signed-out/expired sessions even while the old access token has time remaining. No mutable `user_metadata` is used for authorization.
- OAuth has random 256-bit state, a private SHA-256 state hash, a 10-minute expiry, atomic single-use consumption, originating-session validation and a fixed HTTPS callback. No query-supplied user ID or return URL controls identity.
- Social credentials use AES-256-GCM, a fresh nonce and account/user/provider associated data. The encryption key is a server secret. Neither tokens nor ciphertext are returned to the browser.
- Sensitive definer functions are in `private` with an empty search path. Public wrappers are invokers. Server RPC execution is granted only to `service_role`; ordinary users cannot fetch a credential, alter an outcome or mint credits.
- Post revisions are server-controlled. Conditional updates prevent overwriting another device's version. Editing approved content resets approval; editing/deleting queued content cancels its snapshot. Processing content cannot be edited or deleted. Approval is a deliberate UI action, not proof of a person's identity or judgment.
- Publication needs both an environment gate and a private DB gate. Jobs contain an immutable snapshot/revision and require a matching connected account. Claims lock the post before its job, consistently with editing, and skip busy rows. Lost-lease reconciliation also skips another worker's locks. Claims have leases; ambiguous final responses and lost leases are **uncertain**, never automatically retried. An uncertain job blocks re-enqueueing that post until operator review.
- The final publish call rechecks both gates. No Cron/worker schedule is created. Turning a gate off stops subsequent dispatch; it cannot undo a request already sent to a social platform.
- Outbound provider requests have HTTPS host allowlists, redirect rejection, bounded timeouts and bounded JSON responses. A provider-supplied upload URL must be on LinkedIn's documented upload host/path. Client media URLs cannot select an arbitrary server destination.
- Media requires a supported container signature, MIME, owner path and <=10 MB. Preview links are five minutes; worker fetch links are fifteen minutes. These URLs are bearer capabilities until expiry, so users should not share private previews. Signatures do not establish codec correctness, duration, malware safety or authenticity.
- Private storage is limited to 20 objects/user and 80/bucket; drafts to 200/user and 1,000 total. Limits serialize concurrent insert checks. No new Storage DELETE privilege is granted. Orphaned uploads remain private until separately authorized cleanup; do not delete Storage metadata directly.
- AI consumes 20 free attempts/user/UTC day atomically. If billing is enabled and credits exist, attempts 21–100 consume one paid credit each. Failed attempts count. The server caps content and validates provider output; human review is still required. These quotas do not replace provider-side spend controls.
- Payments use server-defined integer prices, fixed references and hosted checkout. No card/UPI details are stored. Raw HMAC signatures, configured merchant identity, full captured amount and currency are verified. Browser redirects cannot grant credit. Event/order uniqueness prevents duplicate grants, including events arriving before the checkout response is saved.
- Processed refund events reverse the corresponding credits once, including partial refunds. Credits already spent can leave a negative balance; further paid attempts are then blocked. The app does not initiate refunds or any automatic charge. Merchant disputes need operator review.
- Production headers are generated for the configured Supabase origin: CSP without inline scripts/eval, no embedding, no sniffing, HTTPS enforcement, a restrictive permissions policy, and private shell caching. Fonts are local/system. The eventual host must actually apply these headers; producing files does not deploy them.
- Optional Turnstile client support requires proof on login/signup/reset/resend when configured. It rejects malformed configuration and reserved dummy keys on production/public hosts, invalidates proof after attempts, expiration or action/language changes, ignores removed-widget callbacks and offers retry after script failure/readiness timeout. CSP permits only Cloudflare's exact script/frame origin when configured. The feature is currently unconfigured and **not live bot protection**: a matching secret and server verification must be enabled in Supabase Auth. No secret is accepted in the client UI. See `supabase/AUTH_CAPTCHA_SETUP.md`.

## Operator handling

- `uncertain` publication: check the destination profile and provider container/post IDs. Do not create another job until the outcome is established. Keep gates off while diagnosing. There is deliberately no client “retry uncertain” action.
- `uncertain` checkout: check the immutable reference and provider records. Do not blindly repeat the provider POST. A verified paid webhook can reconcile a link whose ID was not saved before a timeout.
- Reconnect: the old workspace credential is replaced atomically; queued jobs on that account are cancelled. Disconnect removes the local token and cancels queued jobs; the user should also revoke the app in Meta/LinkedIn settings. Expired tokens fail closed and require reconnect; partner-only automatic refresh is not assumed.
- Key rotation: create a new 32-byte encryption secret through the approved secret-management flow and reconnect accounts. Do not replace an active key without a planned credential migration; retain no plaintext fallback.
- Incidents: disable the relevant private DB gate and environment gate, stop the worker, rotate compromised server secrets, revoke provider grants and investigate using sanitized IDs/statuses. No raw tokens, authorization codes, passwords or payment payloads belong in logs or issues.
