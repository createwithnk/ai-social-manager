## Available in the development source

The single **Velo tools** navigation entry mounts `src/features/velo/ModuleWorkspace.tsx`. All new styles are scoped to `.velo-tools`. English/Arabic labels use a separate dictionary and the existing locale/RTL context. The original Dashboard, Generator, Calendar, Media and owner screens remain in place.

1. **Asset bridge:** Canonical Canva design and Google Drive file/folder bookmarks. Only clean HTTPS provider links are accepted; credentials, unknown query parameters and arbitrary origins are rejected. Tracking fields and optional Canva share-path segments are discarded. A user must still have provider account access. There are no embedded third-party previews, automatic downloads, permission changes or source-file deletions. The local, versioned bookmark store is scoped by account and capped at 100 links; invalid/corrupt stores are preserved. Browser storage is a convenience, not a server authorization boundary or cross-device sync. Do not save confidential links on shared devices. Removing a bookmark never deletes its original file.
2. **Canva Bulk Create:** Download up to 100 existing saved posts as a UTF-8 CSV with idea, caption, hashtags, language and platform columns. Upload the CSV manually in Canva Bulk Create and map its fields to the chosen template. Formula-leading CSV values are escaped. CSV export does not approve or publish drafts. A 2 TB Google plan is account storage, not automatically connected application capacity, CDN capacity or a per-customer entitlement.
3. **Publisher preparation:** Five connector descriptors and structured preflight plans for Instagram, TikTok, YouTube Shorts, Snapchat and Google Business Profile. Plans display prerequisites and planned stages. Every result is explicitly `preview-only`, `queued=false`, `published=false`; no OAuth/publish button, HTTP transport or queue writes are added. A content digest invalidates stale plans but is not a server approval signature. Core post types are intentionally unchanged: content for platforms absent from the existing schema requires a separately reviewed additive integration before real scheduling. The existing Instagram/LinkedIn server workers and encrypted credential/approval/lease/uncertain-outcome contracts are not replaced.
4. **WhatsApp shadow mode:** A rules-based sample enquiry filter, not a connected LLM or customer inbox. It uses clearly labelled sample English/Arabic FAQs, explicit buying/booking intent, consent-gated handover candidates, per-conversation opt-out and human takeover, bounded processing and message-id deduplication. Inputs and decisions are not persisted, transmitted or logged. Each test conversation can be reset. Sample consent is not real customer permission; a lead label is not a confirmed booking.
5. **Webhook guard foundation:** The unmounted `_shared/velo-whatsapp.ts` verifies the HMAC-SHA256 signature of the exact bounded raw body and matches both WABA and receiving phone id. It is not an HTTP endpoint, subscription, challenge handler, tenant resolver, durable replay store or messaging integration. Those are required before any real webhook is accepted. The sample browser filter must never be used as the production authorization boundary.
